用户看了原型后给的意见：**长截图操作交互不要太复杂——框选以后，鼠标滚动到哪里就截到哪里，用户想结束滚动时给一个操作交互指示就结束，可参考 同类产品。**

查证 同类产品 官方文档：流程是「等待开始（蓝框）→ 点开始 → 采集中（红框）→ 点保存/复制」，右侧带缩略预览和绿/红匹配点。它的核心（滚轮滚、自动认重叠、实时拼接）照搬，砍掉两处：

1. **取消"等待/采集"两态**——框选松手那一帧就开始采集，不需要再点"开始"。
2. **取消独立的"正在拼接"进度页和右侧缩略预览**——滚动中实时拼接，段数与高度直接写在结束条上。

新流程（三段）：
- 阶段 1 框选即开始（松手那帧 = 第 1 段）
- 阶段 2 滚动采集：滚轮在屏幕任何位置都生效；滚动中边框红实线，停手 0.4 秒变红虚线；**结束条贴在选区下沿外侧**，滚动中淡出、停手淡入。三种结束方式等价：点「完成 ↵」/ 按 `Enter` / 选区内双击。到底了不涨数字、文案变「看起来到底了」并脉冲一次，**仍不自动完成**。向上回滚不产生新段。
- 阶段 3 接缝质检：**全部正常就不弹这一页**，直接落盘；有可疑才打开，只列可疑项、正常项折叠成一行，主操作「全部接受」。

**契约层面的取舍**：`Esc` 取消改为**不落盘**（推翻本文档早先的"取消后输出已成功部分"）。与 PRD LONG-6 不冲突——LONG-6 管的是"工具拼接失败不能丢用户的采集"，那是失败保底；用户主动取消就是取消。已写进说明书 §4.4。

同步改动：说明书 §4.4 整节重写（含对 同类产品 的取舍说明）、§0.2 与 §2 的界面对照、新增 §5.2.1「长截图采集态」键位表、§8 长截图验收清单重写为 14 条、§7 错误表拆成"部分接缝可疑（码 0）/ 完全拼不上（码 2）"两条；原型重做 `#sc-guide` 场景为可真实滚动的模拟（鼠标移到窗口上就能滚，段数/高度实时涨）。

### 原型渲染验证手段（本机可用）

`agent-browser` 首次 open 会卡住（疑似拉 Chromium），改用本机 Chrome headless 更快：

```bash
CHROME="/c/Program Files/Google/Chrome/Application/chrome.exe"
"$CHROME" --headless --disable-gpu --hide-scrollbars --window-size=1500,760 \
  --virtual-time-budget=4000 --screenshot=out.png "file:///<绝对路径>#scroll"
```

- 原型已加 **hash 深链**：`#scroll` / `#overlay` / `#panel` 等直接进对应场景，截图和分享都用得上。
- 要看**精确几何数据**（元素位置/尺寸/计算样式）时，别靠读图猜：把探针 JS 写成**独立文件**再注入副本，然后用 `--dump-dom` + `tr '>' '\n'` + grep 出纯文本。用 `node -e` 内联探针时 `\n` 会被 shell 吃成裸换行导致脚本语法错误、静默不执行。
- 覆盖层的遮罩对比靠 `box-shadow: 0 0 0 9999px rgba(0,0,0,.42)` 挖洞；**舞台底色必须是深色**（本原型用 `#2A2A31` 模拟桌面），否则选区内外的亮度差被压平、看不出效果。
