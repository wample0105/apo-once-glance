## 0. 一页结论

### 0.1 产品是什么

一款 **Windows 优先、本地优先、为外部 AI Agent 设计的截图工具**。

它不做一个内容编辑器，也不做 AI 聊天助手，而是把自己定位为 Agent 的「眼睛」：任何支持 MCP 或 shell 的 Agent（ZCode、Claude Code、Codex CLI 等）都可以通过标准化接口完成「截屏 → 取字（带坐标）→ 标注 → 落盘」的完整感知链路，并基于这些素材替用户撰写教程类文章。

对人类用户，它同时是一把不将就的截图工具：全局快捷键、框选、本地 OCR、剪贴板直出，不接 Agent 也完整可用。

产品内部的三方分工，是整个设计的第一性原理：

> **人类负责操作与审美，工具负责感知与记录，Agent 负责理解与成文。**

一句话定位：

> **让 Agent 看见你的屏幕，替你把操作变成教程。**

### 0.2 首版必须成立的三件事

1. **Agent 可靠调用链**：`capture → ocr → annotate → 落盘` 一条 CLI/MCP 链路在 10 秒内可跑通；输出路径、JSON 结构、退出码完全确定，Agent 无需试错。
2. **感知-标注闭环**：OCR 结果必须携带文字坐标（bbox），Agent 即使没有视觉能力，也能据此在截图上精准叠加箭头、步骤序号、马赛克，产出可直接发布的教学配图。
3. **人类裸用不将就**：不接 Agent 时，快捷键 → 框选 → 本地 OCR → 自动复制，本身就是一把完整好用的截图工具。

### 0.3 产品公式

> 专业取字工具 的极短路径（截图即结果）+ 同类产品 的人类标注手感 + 同类工具 长截图的可靠性教训（含反面）+ MCP 生态带来的 Agent 工具接入标准 + 「把写作交给 Agent 生态」的分工。

### 0.4 最重要的产品判断

- **不做文章编辑器**。写作交给 Agent，工具不做「第二个 Notion/公众号后台」。编辑器一旦进场，产品就会和 Agent 生态竞争，而不是补位。
- **工具不配置云模型**。理解、翻译、写作全部由外部 Agent 的模型承担；工具只做本地感知。零 API Key、零云端上传，隐私边界天然干净，这本身就是卖点。
- **坐标是第一公民**。不带 bbox 的 OCR 文本对 Agent 只有半个价值；感知结果的结构化程度决定标注能力的上限。
- **确定性压倒灵活性**。稳定的路径、命名、schema、退出码，比多十个花哨参数更有价值。Agent 编排最怕不确定性。
- **人类裸用是底线**。Agent 模式是增量价值，不是使用门槛；纯人工用户不应感到这个工具「缺一半」。
- **可靠性高于功能数**（行业公认教训，含 同类工具 的臃肿与 同类工具 的剪贴板翻车）：失败必须可见、有明确错误码、可重试。

## 1. 背景与问题定义

### 1.1 痛点：教程创作的「最后一公里」全是手工

写一篇 15 步的软件教程，今天的真实链路：

```text
操作目标软件 → 逐张截图
    → 逐图标注：画箭头、加步骤序号、打码邮箱/Token
    → 从截图里抄出按钮文案、菜单项、报错文字
    → 切到 Markdown / 公众号编辑器，把图和文字按步骤拼起来
    → 导出、改名、插图、调整尺寸
```

这条链路存在三个断点：

- **断点一：截图之后的一切是另一套手工。** 标注要进编辑器、取字要开 OCR 工具、归档要手动命名，动作与「下一步」之间全部断裂。这是截图品类的长期公开痛点，Reddit、GitHub Issues 等社区反复出现同类反馈：截图后二次处理链路长、OCR 丢失结构、剪贴板不可靠、分享与问 AI 时担忧隐私泄露、美化仍要进设计工具。
- **断点二：AI 写作工具看不见屏幕。** 编码 Agent 能写出流畅的教程文字，却拿不到「刚刚那张截图」：不知道图里有什么、按钮在哪、该往哪里画箭头。用户被迫充当人肉中转站：截图 → 保存 → 上传 → 口述界面布局。
- **断点三：截图工具不接待 Agent。** 同类工具/同类产品 功能齐全但没有给 Agent 的稳定接口；用「模拟热键 + 读屏 + 裁剪」拼凑的自动化方案脆弱且不可复现。

### 1.2 为什么现有品类解决不了

| 品类 | 代表产品 | 到位之处 | 差在哪 |
|---|---|---|---|
| 人类截图工具 | 同类产品 / 同类产品 / 同类工具 / 同类工具 X | 快捷键、标注、长截图体验成熟 | 无 Agent 接口；「AI」只是附加按钮 |
| OCR 小工具 | 专业取字工具 / 取字小工具 | 极短路径取字 | 止步于纯文本；无坐标、无标注、无工作流 |
| 自动教程生成器 | Scribe / Tango | 点哪记哪、自动出步骤图 | 锁定「软件操作向导」单一形态；内置黑盒编辑器；无法用自定义 Agent 自由写作 |
| 编码 Agent | ZCode / Claude Code / Codex | 写作与编排能力强 | 看不见屏幕；视觉模型缺坐标基准，标注全靠猜 |

**结论：市场缺的不是又一个截图工具，也不是又一个写作 AI，而是两者之间那条可靠的感知管道。**

### 1.3 为什么是现在

- **MCP 已成为 Agent 工具接入的事实标准**，ZCode、Claude Code、Codex CLI 等主流 Agent 原生支持，工具侧一次实现即可接入整个生态。
- **主流编码 Agent 普遍具备多模态视觉能力**，「Agent 看图写作」的智能部分已经存在，缺的只是可靠、低成本、隐私干净的取图取字管道。
- **「让 Agent 调用截图工具」已被市场初步验证**：已有产品尝试为 Agent 提供截图类工具接口并收获真实关注，证明方向成立；但现有实现均把 Agent 集成做成通用截图工具的附属功能，且 Windows 平台完全缺位。

### 1.4 机会窗口

把上述痛点与能力空白放到一张定位图上，「Agent 视觉层」象限目前是空的：

- 面向人类的截图工具没有 Agent 接口；已出现的 Agent 集成尝试也只是通用工具的附属功能。
- 自动教程生成器（同类教程 SaaS 类）验证了「采集即文档」的真实需求，但形态锁死在软件操作向导，写作环节无法自由交给用户自己的 Agent。
- Windows 是 Agent 用户与内容创作者基数最大的平台，却没有一款把「让 Agent 看见屏幕」作为产品主线的截图工具。

本产品占据这个空位：**Windows 优先、Agent 主线、人类裸用底线、零云端**。与各品类的逐项对照见附录 A。

## 2. 目标用户与核心场景

### 2.1 第一目标用户：使用编码 Agent 的教程与内容作者

典型对象：AI 工具教程作者、技术博主、开发者关系/产品文档工程师、公众号科技栏目作者——已经把 ZCode/Claude Code 纳入日常写作流程的人。

高频任务：

- 把某个软件/网站的新功能体验写成图文教程（10–30 步）。
- 把终端/命令行操作过程写成入门指南（截图 + 命令与输出文字）。
- 批量给存量教程更新截图并重新标注（版本升级后 UI 变了）。
- 产出中英双语的步骤图（Agent 直接基于 OCR 文本翻译并生成标注版本）。

### 2.2 第二目标用户：想让 Agent「看见屏幕」的开发者与自动化用户

- 把报错截图连同界面上下文一起交给 Agent 分析。
- 自动化脚本（E2E 测试、RPA）产出带标注的「证据截图」。
- 在文档流水线里批量生成带序号标注的配图。

### 2.3 第三目标用户：普通截图用户（人类裸用模式）

不需要理解任何 Agent 概念：快捷键截图、自动取字、标注、长截图，行为与主流截图工具一致。这一群体是口碑传播的基数，也是冷启动期的自然用户。

### 2.4 Jobs-to-be-Done

主 JTBD：

> **当我让 Agent 替我写一篇操作教程时，我想让它自己拿到每一步的截图和界面文字，并直接产出带序号、箭头和打码的配图成稿，这样我不必逐张截图、逐图标注、逐段抄字。**

辅助 JTBD：

> 当我截屏时，我想立刻得到可粘贴的图片或文字，而不打开任何窗口。

> 当 Agent 替我处理屏幕内容时，我想清楚地知道它拿到了什么、传给了谁，并能一键切断。

### 2.5 场景故事走查

**S1 · 教程全流程（第一用户的完整一天）**

作者在 ZCode 里输入：「我要写一篇 XX 工具数据看板功能的教程，我现在开始操作，你按步骤帮我截图、记录、最后成稿。」作者在目标软件里逐步操作，每完成一步按下全局快捷键截图（或 Agent 通过 MCP 主动截取当前窗口）。Agent 收到每张截图的落盘路径 + OCR 文本（含按钮 bbox 坐标），累计 14 步后，Agent 生成标注脚本：给每张图加步骤序号、给关键按钮画箭头、把作者邮箱区域打码。渲染完成后，Agent 按 Skill 约定的 Markdown 结构输出整篇教程，配图引用相对路径。作者通读修订，发布。全程未打开图片编辑器，未手动抄一个字。

**S2 · 报错分析（第二用户）**

终端里出现一个渲染异常。用户按下「截图并询问 Agent」流程：CLI 截取终端窗口 → OCR 提取报错文本与堆栈 → Agent 结合 OCR 文本（无需读图，节省视觉 token）给出定位。OCR 置信度低的区域会被 Agent 主动用视觉模型复核。

**S3 · 裸用取字（第三用户）**

用户在网页上看到一段不可复制的表格文字，按下「自动取字」快捷键、框选，松手——文字已在剪贴板，屏幕角落 toast 显示「已复制 216 字 · 本地完成」。没有窗口，没有上传。

## 3. 产品定位、边界与原则

### 3.1 定位声明

> 定影（Onceglance）是 Agent 时代的屏幕感知层：人类用它截图，Agent 用它看屏幕；它负责把屏幕内容变成结构化、可标注、可引用的素材，不负责替你写一个字——写，是 Agent 的事。

### 3.2 产品边界

**做（v1）**：区域/窗口/全屏捕获、滚动长截图、本地 OCR（带坐标）、指令驱动标注、人类兜底标注、剪贴板与确定性落盘、CLI + MCP + Agent Skill 三接口、本地历史索引、隐私黑名单与审计。

**明确不做（愿景级非目标）**：

- 不做文章编辑器、富文本排版或公众号后台。
- 不做云服务、账号体系、团队协作与分享外链。
- 不做聊天框——「问 AI」是 Agent 的事。
- 不做录屏视频与 GIF 录制（P2 亦不承诺）。
- 不做全天候屏幕监控或「数字记忆」类产品；只在用户或 Agent 主动触发时读取屏幕。
- 不内置任何云端模型配置；需要云视觉时，用户应使用其 Agent 自带的能力。

### 3.3 设计原则

1. **Agent 是第一公民，人类裸用是底线**：每个功能都先定义 CLI/MCP 语义，再定义 UI；但每个 UI 功能也必须能脱离 Agent 独立使用。
2. **确定性压倒灵活性**：路径、命名、JSON schema、退出码一经发布即冻结；变更必须升主版本号并在 Skill 中声明。
3. **坐标是第一公民**：OCR 输出必须携带分块 bbox；全链路统一物理像素坐标系（另提供相对坐标入参）。
4. **本地优先，隐私即卖点**：零云端请求、零遥测；能离线完成的不联网。
5. **结果优先，不打断**：截图到结果全程 toast 化反馈，不弹主窗口、不抢焦点。
6. **一套引擎，两个入口**：人类 UI 与 Agent 接口共享同一捕获/OCR/标注渲染内核，行为与输出完全一致；人类标注 UI 只是渲染引擎的另一个前端。
7. **可靠性高于功能数**：每个失败路径都有明确错误码与恢复建议；剪贴板、捕获、拼接失败必须用户可见。

## 4. 核心概念模型

### 4.1 双模式

```text
┌────────────────────────────────────────────────────────┐
│                    同一内核（捕获/OCR/标注/历史）          │
├────────────────────────────┬───────────────────────────┤
│      人类快捷键模式          │       Agent 接口模式        │
│  全局热键 → 框选 → toast     │  CLI / MCP / Skill         │
│  结果进剪贴板 + 落盘         │  结果 = JSON + 确定性路径    │
│  兜底标注 UI                │  标注脚本（JSON）           │
└────────────────────────────┴───────────────────────────┘
```

两种模式共享历史与设置；人类截的图 Agent 可以继续处理（`once ocr last`），Agent 截的图人类可以在托盘历史里查看。

### 4.2 Capture Artifact（截图资产）

一次捕获产生一个资产，包含：

- `image`：原图 PNG（永不覆盖、永不修改）。
- `manifest`：同名 JSON（捕获类型、来源窗口标题与 PID、屏幕编号、物理尺寸、DPI 缩放、时间戳、资产 id）。
- `ocr`：OCR 结果 JSON（异步生成，可缺失）。
- `derivatives`：标注版本、裁剪版本等衍生图（记录 lineage 指回原图）。

衍生图不覆盖原图是硬性规则：Agent 的任何批处理都不允许破坏用户素材。

### 4.3 感知-标注闭环 ★ 本产品的灵魂设计

传统工具里「取字」和「标注」是两件事；本产品用同一个坐标体系把它们变成一件事：

```text
截图 → OCR（文本 + 分块 bbox）
          ↓
Agent 决策：这段文字就是要指的地方
          ↓
生成标注脚本（引用 bbox 坐标，或 0–1 相对坐标）
          ↓
标注渲染引擎 → 教学配图
```

两种坐标来源，覆盖两类 Agent：

- **OCR bbox（绝对像素）**：文本 Agent 无视觉能力也能精准标注——「给『导出报表』按钮画箭头」= 取该文本 block 的 bbox 右侧偏移 20px。
- **相对坐标（unit=rel，0–1）**：视觉 Agent 按看到的画面比例给出坐标，引擎按图片实际尺寸换算，规避 Agent 数错像素。

标注脚本示例：

```json
{
  "source": "2026-09-17/143012-window-a1b2.png",
  "output": "2026-09-17/143012-window-a1b2-ann.png",
  "unit": "px",
  "operations": [
    { "type": "step_number", "at": [120, 80], "label": 1 },
    { "type": "arrow", "from": [400, 120], "to": [612, 214], "color": "#FF3B30" },
    { "type": "rect", "at": [560, 190], "size": [104, 48], "style": "outline" },
    { "type": "mosaic", "at": [80, 940], "size": [220, 36], "mode": "pixelate" }
  ]
}
```

### 4.4 确定性输出约定（对 Agent 友好的契约）

- 落盘根目录：`%USERPROFILE%\Pictures\Onceglance\`，按日期分子目录；可在设置中更改，更改后 CLI/MCP 立即感知。
- 默认命名：`HHmmss-<kind>-<shortid>.png`，同名 `.json` 为 manifest；`--out` 可完全覆盖。
- 所有命令输出统一 JSON envelope：

```json
{ "ok": true, "data": { }, "error": null, "meta": { "version": "1.0.0", "elapsed_ms": 214 } }
```

- 退出码契约：`0` 成功；`1` 参数错误；`2` 捕获失败；`3` OCR 失败；`4` 文件读写失败；`5` 桥接/权限被拒；`6` 隐私黑名单拦截。Agent 依据退出码即可决定重试或放弃，无需解析自然语言。

### 4.5 信任边界

- Agent 桥接仅监听当前用户的本地 Named Pipe（ACL 限定当前用户）；MCP 走 stdio，无网络监听。
- 设置提供「允许 Agent 调用」总开关（默认开，可一键关闭）与**隐私 App 黑名单**：目标窗口标题/进程匹配黑名单（银行、密码管理器等，内置常见条目 + 用户自定义）时拒绝捕获并返回错误码 6。
- 审计日志只记录元数据（时间、命令、耗时、结果状态、目标进程名），**永不记录**图片内容与 OCR 正文，可一键清空。
- 常驻零遥测、零自动更新上报。

## 5. 版本范围与优先级

### 5.1 优先级定义

- **P0**：v1.0 发布阻塞项，缺失则产品定位不成立。
- **P1**：v1.x 快速跟进，增强体验但不影响定位。
- **P2**：方向性蓝图，进入前需重新过准入规则。

### 5.2 v1.0 P0 清单

| 编号 | 能力 |
|---|---|
| P0-01 | 应用外壳：托盘常驻、开机自启（可选）、设置窗口、全局快捷键（录制/冲突检测） |
| P0-02 | 捕获：区域框选、当前窗口、全屏、延时截图；多屏 + 混合 DPI；捕获时隐藏自身 |

## 6. 功能需求与验收标准

> 约定：验收标准均为可测口径；「物理像素」指不含 DPI 缩放的真实像素。全部需求同时约束人类 UI 与 Agent 接口两个入口。

### 6.1 SYS · 应用外壳与快捷键

| 编号 | 需求 |
|---|---|
| SYS-1 | 托盘常驻：左键呼出主面板（历史 + 最近捕获），右键菜单含设置/暂停 Agent/退出 |
| SYS-2 | 全局快捷键默认值：区域截图 `Alt+Shift+A`、自动取字 `Alt+Shift+T`、长截图 `Alt+Shift+L`、窗口截图 `Alt+Shift+W`、全屏 `Alt+Shift+F`；全部可录制修改 |
| SYS-3 | 快捷键注册失败（冲突/被占）必须在设置中可见，并提供冲突来源提示与一键改键建议 |
| SYS-4 | 开机自启默认关闭，开启走任务计划/注册表标准方式 |
| SYS-5 | 退出必须释放全部热键、Named Pipe 与钩子；再次启动不得出现残留实例（单实例锁） |

**验收标准**

- 热键按下到框选浮层出现 ≤ 200ms（单屏 1080p、无高负载场景，P95）。
- 在注册了相同热键的其他常驻软件启动后，本工具设置页能在 5 秒内标出冲突项。
- `once doctor` 能依次报告：实例状态、热键注册结果、捕获自检结果、桥接监听状态、默认落盘目录可写性。

### 6.2 CAP · 捕获

| 编号 | 需求 |
|---|---|
| CAP-1 | 区域框选：跨屏光标跟随、放大镜取像素、尺寸提示、`Esc`/右键取消且无任何副作用（不落盘、不改剪贴板） |
| CAP-2 | 窗口捕获：悬停高亮窗口自动吸附（含浏览器标签页级识别尽力而为）；捕获内容不含捕获工具自身 |
| CAP-3 | 全屏捕获：支持指定显示器与 `--screen all` |
| CAP-4 | 延时截图：`--delay <秒>`；UI 提供 1/3/5 秒预设 |
| CAP-5 | 多屏与混合 DPI：所有坐标与裁剪基于物理像素；manifest 记录 `dpi_scale` 与屏幕布局快照 |
| CAP-6 | 捕获瞬间自动隐藏自身浮层；1000ms 内完成捕获恢复，全过程不抢键盘焦点 |
| CAP-7 | 任何捕获路径（含 Agent 触发）均遵守隐私黑名单（见 §6.10） |

**验收标准**

- 主屏 150% 缩放 + 副屏 100% 的双屏环境：框选区域与落盘图片逐像素一致（边界容差 ≤ 1px）。
- 区域截图从确认到图片进剪贴板 ≤ 500ms（1080p，P95）。
- 捕获本工具自身可见时，成图中不得出现工具 UI（自hide 断言测试）。
- `Esc` 取消 100 次压力测试：0 次残留临时文件、0 次剪贴板污染。

### 6.3 OCR · 本地识别

| 编号 | 需求 |
|---|---|
| OCR-1 | 引擎：Windows 内置 OCR 为 v1 默认；引擎层做 Provider 抽象，为 P1 本地增强包留位 |
| OCR-2 | 输出结构：`blocks[]`（`type: text|code|table|ui`，`text`、`bbox`、`confidence`、`lines[]`）+ `full_text` + 检测语言 |
| OCR-3 | 中英混排与常见标点、段落顺序保持；代码片段合并为 `code` block（缩进尽力保持） |
| OCR-4 | 低置信度（< 0.75）block 必须携带标记，供 Agent 决定复核；工具自身不静默丢弃 |
| OCR-5 | 结果缓存：同一图片重复 OCR 命中缓存（按内容哈希） |

**验收标准**

- 清晰屏摄场景（Windows 11 设置页、VS Code、Chrome）：中文识别准确率 ≥ 97%，英文 ≥ 98%（以人工标注 200 张样本集为基准，M1 建立基线后持续回归）。
- 1080p 截图 OCR 耗时 P95 ≤ 1500ms（内置引擎，Reference PC）。
- `once ocr last --json` 的 `blocks[].bbox` 与对应文字在原图上的位置误差 ≤ 文字高度的 50%（抽样人工核验 ≥ 50 个 block）。
- 无文字图片返回 `ok: true` + 空 blocks + `data.empty_reason`，不得报错。

### 6.4 CLP · 剪贴板与落盘

| 编号 | 需求 |
|---|---|
| CLP-1 | 剪贴板多格式写入：PNG 位图 + DIB + 文件路径（CF_HDROP）同时提供；写入后读回校验 |
| CLP-2 | OCR 文本复制不得覆盖用户在识别期间新写入的剪贴板内容（比对时间戳/序列号） |
| CLP-3 | 确定性落盘：目录与命名见 §4.4；`--out` 指定时跳过默认目录 |
| CLP-4 | manifest 随图生成；衍生图 lineage 指回原图 id |
| CLP-5 | 保存失败（磁盘满/权限）必须 toast + 错误码 4，且不影响剪贴板结果 |

**验收标准**

- 粘贴到 Word、微信、VS Code、Chrome：均能得到清晰图片（目标矩阵进 M3 回归清单）。
- 复制文本后触发 OCR 取字：识别完成时若剪贴板序列号已变化，不得覆盖；toast 提示「剪贴板已有新内容，文字已保存至 …」（属于读写失败，退出码 4，见 §9）。
- 断言：任何成功路径下，返回给调用方的路径必然存在且可读。

### 6.5 LONG · 滚动长截图

| 编号 | 需求 |
|---|---|
| LONG-1 | 手动滚动捕获：用户框选区域并手动滚动，工具按间隔采样拼接 |
| LONG-2 | 拼接算法：相邻帧位移匹配、重复帧过滤、滚动方向识别 |
| LONG-3 | 固定区域消除：识别并只保留一份固定标题栏/底栏/侧栏 |
| LONG-4 | 接缝检查：完成后标注可疑接缝，支持 ±1/±10px 人工修正 |
| LONG-5 | 超长图分段导出（可配置段高），避免内存失控 |
| LONG-6 | 拼接失败时输出已成功部分 + 明确失败原因，不静默丢弃 |

**验收标准**

- 无限滚动网页、聊天窗口、文件管理器三类场景各 10 个用例：拼接成功且无重复/缺口 ≥ 8 例；失败例必须能通过人工修正达成可用。
- 20000px 高度长图导出内存峰值 ≤ 2GB，且提供分段导出后 ≤ 800MB。
- 固定标题栏在成图中恰好出现 1 次（用例断言）。

### 6.6 ANN · 指令驱动标注

| 编号 | 需求 |
|---|---|
| ANN-1 | 标注脚本 schema v1（§4.3），操作类型：`arrow / rect / ellipse / step_number / text / highlight / mosaic(pixelate|blur) / crop` |
| ANN-2 | 坐标系：默认物理像素 `px`；支持 `unit: rel`（0–1 相对坐标）；支持引用 OCR block id 作为坐标锚点（`anchor: "block:3"` + 偏移） |
| ANN-3 | 渲染参数（颜色、线宽、字号、序号样式）提供有品位的默认值；脚本可覆盖 |
| ANN-4 | 衍生图落盘不覆盖原图；输出 manifest 含所引用的脚本内容哈希（可复现） |
| ANN-5 | 非法脚本（越界坐标、未知类型、超 200 操作）整单拒绝并返回逐条错误，不产出半成品 |
| ANN-6 | 人类兜底标注：预览浮层提供箭头/矩形/文字/序号/马赛克工具，保存走同一渲染引擎，产出同为衍生图 |
| ANN-7 | 步骤序号支持批量语义：`step_number` 按 `at` 出现顺序自动编号，或显式 `label` |

**验收标准**

- 用 OCR bbox 锚点给「设置」按钮加箭头：箭头终点与按钮实际位置偏差 ≤ 8px（Reference PC，标准 DPI）。
- 同一脚本重复渲染 10 次：输出文件哈希完全一致（确定性断言，字体渲染子像素差异需消除）。
- 视觉 Agent 以 `unit: rel` 提交坐标：1080p 与 4K 同源截图渲染结果构图一致。
- 人类标注 UI 完成一张 5 步序号图 ≤ 60 秒（可用性测试通过率 ≥ 4/5）。

### 6.7 CLI · `once` 命令规范

```text
once status                                # 版本、实例、桥接、热键状态
once capture region  [--out P] [--screen N|--screen all] [--delay S]
once capture window  [--title T | --pid N] [--out P]
once capture fullscreen [--screen N|all] [--out P]
once capture scroll  [--out P] [--max-height H] [--segments]
once ocr <path | last> [--lang auto] [--json]        # blocks + bbox
once annotate <path | last> --script F --out P
once history [--limit N] [--query Q] [--json]        # FTS 检索
once open <id | path>                       # 在资源管理器中定位
once config get <key> | config set <key> <value>
once doctor
once mcp                                    # 以 stdio 启动 MCP Server
```

| 编号 | 需求 |
|---|---|
| CLI-1 | 所有命令支持 `--json`（envelope 见 §4.4）；人类模式输出简洁文本 |
| CLI-2 | 退出码契约见 §4.4，一经发布冻结 |
| CLI-3 | 单文件可执行，冷启动（不含捕获）≤ 300ms |
| CLI-4 | `last` 语义：当前用户最近一次成功捕获（含 Agent 触发的），跨进程共享 |
| CLI-5 | CLI 与 GUI 可独立运行：无 GUI 时 CLI 直接驱动内核；GUI 在线时共享历史与设置 |

**验收标准**

- 脚本化冒烟：`once capture window --json → once ocr last --json → once annotate last --script s.json --out r.png` 三命令链在 10 秒内成功完成（Reference PC）。
- 全部命令在 PowerShell、CMD、Git Bash 下行为一致（路径、编码 UTF-8 无 BOM）。
- 错误注入（无效路径、越界坐标、黑名单应用）分别返回退出码 4/1/6，且 envelope.error 含人类可读与机器可读 code。

### 6.8 MCP · Server 规范

| 编号 | 需求 |
|---|---|
| MCP-1 | 传输：stdio；由 `once mcp` 启动，Agent 侧注册为本地 MCP Server |
| MCP-2 | 工具集：`capture_screen(kind: region|window|fullscreen, …)`、`scroll_capture(…)`、`ocr_image(path|last)`、`annotate_image(path|last, script)`、`list_history(query, limit)`、`doctor()` |
| MCP-3 | 工具返回结构化文本（envelope JSON），路径字段使用绝对路径；资源（resource）暴露最近捕获 manifest |
| MCP-4 | 参数校验错误返回结构化错误（code + message + hint），不抛裸异常 |
| MCP-5 | Server 无网络监听、无常驻后台任务；随 Agent 会话生命周期运行 |

**验收标准**

- ZCode / Claude Code Desktop 以标准配置接入后，无需人工干预完成「截图 → 取字 → 标注」三工具链。
- 工具描述文本自含（Agent 不读外部文档即可正确调用，M0 末以 3 个主流 Agent 实测）。

### 6.9 SKL · Agent Skill 规范

| 编号 | 需求 |
|---|---|
| SKL-1 | 随发行版提供「教程写作工作流」Skill（Markdown + 参考脚本），安装到通用 Agent Skills 目录 |
| SKL-2 | 内容：接口速查、教程写作 SOP（按步捕获 → OCR 记录 → 标注脚本生成 → Markdown 组稿 → 相对路径引用）、坐标与单位约定、错误处理建议 |

### 6.10 SET · 设置、隐私与审计

| 编号 | 需求 |
|---|---|
| SET-1 | 设置项：热键、默认落盘目录、截图后默认动作（复制图片/取字复制/仅保存）、OCR 引擎、长截图参数、语言 |
| SET-2 | 「允许本机 Agent 调用定影」总开关：CLI、Agent Skill 与 MCP 经仅限当前用户的本机桥接调用，不开放网络端口；关闭后截图类命令返回退出码 5，只读命令（history/status）不受影响 |
| SET-3 | 隐私 App 黑名单：内置常见敏感应用条目，支持按进程名/窗口标题关键字添加；命中即拒（错误码 6）且不留成图 |
| SET-4 | 审计日志：本地 JSONL，仅元数据（时间、命令、耗时、状态、目标进程名）；设置页可查看与一键清空 |
| SET-5 | 全量设置本地存储，不包含任何密钥（本产品无密钥概念） |
| SET-6 | Agent 与自动化附加开关：「允许无感自动截图」（默认开）——静默截图不弹出取景层、不抢占前台 App、不模拟键鼠；黑名单与审计日志依旧生效；总开关关闭时该开关置灰 |
| SET-7 | 标注样式记忆：标注编辑器是唯一调参入口，参数改动自动"记住上次"成为新默认（可整体关闭）；「标注主题」页只读管理——查看当前默认值、恢复出厂、导入/导出预设，不提供第二套调参控件 |

**验收标准**

- 将「记事本」加入黑名单后，对其窗口执行 `once capture window --title 记事本`：返回码 6、无文件产生、审计日志记录一次拦截（仅进程名）。
- 关闭 Agent 开关后，MCP 捕获工具在 Agent 侧收到明确的权限错误文案。

## 7. 关键用户流程

### 7.1 首次启动与 Agent 接入

```text
安装 → 权限/环境自检（热键、捕获、落盘目录）→ 引导页（30 秒：裸用三连拍演示）
    → 「接 Agent？」可选引导：安装 CLI 与 Skill（一条命令，终端或交给 Agent 代跑）/ 配置 MCP
    → 未接 Agent 的用户直接进入裸用，不受任何阻断
```

### 7.2 端到端：Agent 写一篇 10 步教程

```text
人类：在 ZCode 下达写作指令，开始操作目标软件
  ├─ 每完成一步：按热键截图（或 Agent 调 capture window）
  ├─ Agent 收到：绝对路径 + manifest + OCR blocks（文本 + bbox）
  ├─ Agent 记录步骤要点（OCR 文本即素材，无需读图）
  ├─ 全部步骤完成：Agent 生成标注脚本（序号 + 箭头 + 打码）
  ├─ once annotate 批量渲染 → 衍生图路径回传
  └─ Agent 按 Skill 约定输出 Markdown 教程（配图相对路径），人类审阅发布
```

### 7.3 人类裸用：截图即结果

热键 → 框选 → 松手 → toast「已复制 · 本地完成」→ 粘贴。自动取字模式默认关闭、一键开启；开启后松手即文字进剪贴板。

### 7.4 长截图

热键 → 框选区域 → 提示开始滚动 → 用户滚动 / （P1）自动滚动 → 停止 → 拼接与质检 → 接缝确认浮层（可修正）→ 落盘 + 剪贴板。

### 7.5 标注往返（含纠错）

Agent 提交脚本 → 渲染 → 若 Agent 坐标有误，人类在托盘历史打开衍生图 → 兜底标注 UI 拖拽修正 → 另存新衍生图（lineage 保留）。工具不假设 Agent 永远正确。

## 8. 隐私、安全与数据边界

1. **零云端**：全链路无网络请求（更新检查显式手动触发且可关）。截图、OCR 文本、审计日志永不离开本机。
2. **最小捕获**：不持续录屏、无后台轮询；只有主动捕获动作读取屏幕。
3. **桥接安全**：Named Pipe ACL 限当前用户；MCP 仅 stdio；无远程端口。可选的 WSL 桥（若做）默认关闭且仅绑定 127.0.0.1。
4. **黑名单与开关**：Agent 总开关 + 隐私 App 黑名单双闸门；拦截行为对 Agent 显式报错而非静默。
5. **审计不含内容**：日志只有元数据；默认保留 30 天自动清理。
6. **供应链**：开源构建可复现；发行物提供 SHA-256 校验；不静默下载模型权重（P1 增强包显式安装）。
7. **代码签名**：目标使用受信任证书签名（成本见 §15）；未签名阶段在 README 明确引导 SmartScreen 放行步骤。

## 10. 技术方案建议（不锁死）

### 10.1 决策原则

- 本产品 80% 的难度在**系统能力**（捕获浮层、多屏 DPI、热键、剪贴板、Named Pipe），20% 在 UI；选型必须让系统能力层可控。
- 常驻内存与冷启动是 Agent 工具用户的核心敏感点。
- 架构按「内核库 + 两个前端（GUI / CLI+MCP）」分层，前端可替换，内核是资产。

### 10.2 应用框架候选对比

| 方案 | 优势 | 风险 | 结论 |
|---|---|---|---|
| **Tauri 2 + Rust（windows-rs）** | 二进制小、常驻内存低、天然跨平台预留（macOS 后续）；系统能力用 Rust 直连 Win32/WinRT | 框选浮层与多屏 DPI 需自研；生态较新 | **主推**，M0 Spike 验证 |
| Electron + 原生 addon | UI 迭代最快、示例最多 | 内存与包体大；系统能力仍需原生 addon，两头成本 | 备选（Spike 失败降级） |
| C# / WinUI 3（或 WPF） | Windows 集成最佳、团队单语言 | 锁死单平台；跨平台要二次重写 | 备选（若放弃跨平台预留） |
| Qt（C++） | 原生性能与浮层控制强 | 开发效率、授权与体积 | 不推荐 |

推荐栈（建议而非约束）：**Tauri 2（UI/托盘/设置）+ Rust 内核（windows-rs：Windows.Graphics.Capture 捕获、Windows.Media.Ocr OCR、Named Pipe 桥接、 RegisterHotKey 热键）+ SQLite（历史索引）+ RapidOCR-onnx 预留（P1）**。

### 10.3 关键组件建议

- 捕获：优先 Windows.Graphics.Capture（FreeThreaded），区域裁剪在物理像素域完成；GDI BitBlt 作为兼容回退。
- OCR：Provider trait（`ocr(image, lang) -> blocks`）；v1 实现 Windows.Media.Ocr；bbox 由引擎 line-level 结果聚合。
- 标注渲染：内核内自绘（如 tiny-skia/skia-safe），禁用系统抗锯齿差异源，保证确定性输出（§6.6 可复现断言）。
- 桥接：Named Pipe（`\\.\pipe\once-bridge`）+ JSON-RPC；MCP Server 进程复用同一内核库。
- 历史索引：SQLite + FTS5；图片缩略图缓存目录与资产目录分离。

### 10.4 M0 Spike 清单（技术验证闸门）

1. Tauri 2 多屏覆盖层在 100%/150%/200% 混合 DPI 下坐标精度 ≤ 1px。
2. 捕获链路延迟：热键 → 位图内存 ≤ 300ms（1080p）。
3. Windows.Media.Ocr 中文样本基线（≥ 97% 达标率？）与 bbox 质量。
4. WebView2 常驻内存 ≤ 150MB；CLI 冷启动 ≤ 300ms。
5. Named Pipe 与 stdio MCP 双通道 PoC。

> 任一项不达标：降级路径为 Electron（1/4 项）或调整对应 P0 验收口径（2/3 项，需记录决策）。
